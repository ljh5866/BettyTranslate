# 05 开发计划与里程碑

> 版本：v0.1 | 日期：2026-08-22 | 状态：待评审

## 1. 里程碑总览

| 里程碑 | 目标 | 交付物 |
|---|---|---|
| M0 环境与上游接入 | 拉取 STranslate 源码并成功编译运行 | 可运行的 STranslate 基础工程 |
| M1 登录体系 | 接入 Supabase Auth，登录后解锁功能 | 登录/注册页 + 会话管理 |
| M2 屏幕翻译 MVP | 快捷键 → 确认弹窗 → 全屏 OCR → 翻译 → 悬浮窗 | 核心功能可用 |
| M3 设置与打磨 | 快捷键/引擎/语言配置、多屏兼容、稳定性 | 完整 V1.0 |
| M4 打包发布 | 安装包、自动更新、发布物料 | V1.0 正式版 |

## 2. 任务拆分

### M0：环境与上游接入

- [ ] 安装 .NET 8 SDK、Visual Studio 2022（.NET 桌面开发负载）
- [ ] Clone `ZGGSONG/STranslate`，编译并运行（含 PaddleOCR 模型下载）
- [ ] 精简依赖：删除不需要的服务插件，保留核心（**只保留要用的库**）
- [ ] 建立 Git 仓库与分支策略，提交基础工程

### M1：登录体系（Supabase Auth）

- [ ] 创建 Supabase 项目，启用 Email Auth
- [ ] 接入 `supabase-csharp`，封装 `IAuthService`
- [ ] 登录页 UI（邮箱+密码、注册、忘记密码）
- [ ] 会话持久化（DPAPI 加密存储 RefreshToken）
- [ ] 启动时恢复会话；未登录时禁用翻译快捷键
- [ ] 退出登录

### M2：屏幕翻译 MVP（核心）

- [ ] 全局快捷键 `F1`（RegisterHotKey）封装
- [ ] 「是否进行屏幕翻译？」确认弹窗（是/否）
- [ ] `CaptureService`：全屏截图（多显示器/DPI 换算，参考 pingyi 方案）
- [ ] `OcrService`：接入 PaddleOCR（独立进程/JSON 通信）；Windows OCR 作为降级
- [ ] `TranslateService`：默认接入百度翻译，抽象 `ITranslateProvider`
- [ ] `OverlayService`：置顶半透明悬浮窗（原/译对照、拖动、复制、关闭）
- [ ] 端到端联调：F1 → 确认 → 扫描 → 中文译文悬浮窗

### M3：设置与打磨

- [ ] 设置页：快捷键、源/目标语言、翻译引擎、OCR 引擎、悬浮窗样式
- [ ] 多显示器、150%/200% DPI 验证修复
- [ ] 悬浮窗「排除自身窗口」防自翻译
- [ ] 错误处理与降级：OCR 失败、翻译限流、断网
- [ ] 日志（Serilog）与崩溃防护
- [ ] 单元测试：OCR 解析、翻译批量、配置读写

### M4：打包发布

- [ ] PaddleOCR 模型随安装包分发（或首次启动下载）
- [ ] 发布配置（x64、单文件可选）、图标、版本号
- [ ] 打包为 MSIX / Inno Setup 安装包
- [ ] 发布说明与用户文档

## 3. 优先级与风险

| 风险 | 等级 | 应对 |
|---|---|---|
| PaddleOCR 集成复杂（进程通信） | 高 | 先用 Windows OCR 快速打通 MVP，再切换 PaddleOCR |
| 多显示器/DPI 截图偏移 | 中 | 优先验证，参考 pingyi 修复代码思路 |
| 在线翻译接口限流 | 中 | 多引擎轮换 + 节流 + 缓存 |
| STranslate 代码量大、耦合高 | 中 | 按模块裁剪，逐步替换，保持可编译 |
| Supabase 网络受限 | 低 | 提供登录超时提示与重试 |

## 4. 验收标准（对应 PRD 第 6 节）

1. 未登录无法触发翻译；登录后可正常使用。
2. 按 `F1` 弹出「是否进行屏幕翻译？」；「是」→ <3s 完成全屏英文 → 中文悬浮窗；「否」→ 取消。
3. 悬浮窗可拖动、可关闭、文本可复制。
4. 断网时 OCR 仍可用，翻译给出明确错误提示。
5. 多显示器 + 高 DPI 下截图无偏移。
