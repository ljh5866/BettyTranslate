# 04 系统架构设计

> 版本：v0.1 | 日期：2026-08-22 | 状态：待评审

## 1. 总体架构（分层）

```
┌─────────────────────────────────────────────────────────────┐
│                       表现层（WPF UI）                        │
│  登录页 │ 设置页 │ 悬浮窗(Overlay) │ 确认弹窗 │ 托盘 │ 结果卡  │
└──────────────────────────┬──────────────────────────────────┘
                           │ MVVM (Command / Event)
┌──────────────────────────▼──────────────────────────────────┐
│                       应用服务层                              │
│  AuthService │ HotkeyService │ CaptureService │ OcrService  │
│  TranslateService │ OverlayService │ SettingsService         │
└───────┬────────────────────┬───────────────────┬────────────┘
        │                    │                   │
┌───────▼────────┐ ┌─────────▼──────────┐ ┌──────▼─────────────┐
│ 基础能力层       │ │  OCR/翻译引擎      │ │   基础设施          │
│ 截图封装        │ │  PaddleOCR(进程)   │ │  Supabase Client   │
│ (WinGraphics)  │ │  Windows OCR       │ │  JSON 配置/日志     │
│ 全局热键 Win32  │ │  百度/DeepL/Google │ │  DPAPI 安全存储     │
└────────────────┘ └────────────────────┘ └────────────────────┘
```

## 2. 模块职责

| 模块 | 职责 | 对应上游 |
|---|---|---|
| `AuthService` | 登录/注册/会话刷新/退出；会话本地持久化（DPAPI） | 新增 |
| `HotkeyService` | 注册全局快捷键 `F1` 等（RegisterHotKey） | 复用 STranslate |
| `CaptureService` | 全屏/区域截图；多显示器与 DPI 换算 | 复用/改造 STranslate + pingyi 经验 |
| `OcrService` | 抽象 `IOcrEngine`：PaddleOCR（默认）/ Windows OCR（备选） | 复用 STranslate 抽象层 |
| `TranslateService` | 抽象 `ITranslateProvider`：百度/DeepL/Google/OpenAI | 复用 STranslate 多引擎体系 |
| `OverlayService` | 置顶半透明悬浮窗（原/译对照、拖动、复制、关闭） | 借鉴 Translumo 设计 |
| `ScreenTranslateFlow` | 屏幕翻译编排：快捷键→确认弹窗→截图→OCR→翻译→悬浮窗 | 新增核心 |
| `SettingsService` | 快捷键/语言/引擎/悬浮窗样式等本地配置 | 复用 STranslate |

## 3. 核心流程时序

### 3.1 登录流程

```
用户 ──输入邮箱密码──▶ LoginWindow ──▶ AuthService.SignIn()
        ◀──Session──  supabase-csharp ──▶ Supabase Auth
        ──DPAPI 加密──▶ 本地存储 RefreshToken
用户 ──启动 App──▶ 检测本地会话 ──有效──▶ 直接进入主界面（免登录）
                            └─无效─▶ 停留登录页
```

### 3.2 屏幕翻译流程（核心）

```
1. 用户在其他软件中按 F1
2. HotkeyService 捕获全局热键
3. ScreenTranslateFlow 弹出确认弹窗「是否进行屏幕翻译？」【是/否】
4. 用户点「是」
5. CaptureService 截取全屏（多显示器/DPI 适配）
6. OcrService 识别文本块（含坐标、置信度）【失败→自动降级到 Windows OCR】
7. TranslateService 批量翻译（在线引擎，去重缓存）
8. OverlayService 以悬浮窗展示：原文块坐标附近 + 译文对照
9. 用户可拖动/复制/关闭悬浮窗
```

### 3.3 错误与降级

- OCR 全部失败 → 提示「识别失败，可重试或调整区域」
- 翻译请求失败（限流/断网）→ 提示错误并保留原文，支持一键重试
- 未登录 → 拦截快捷键，提示先登录

## 4. 关键接口设计（草案）

```csharp
public interface IOcrEngine
{
    Task<OcrResult> RecognizeAsync(Bitmap screenImage);
}

public interface ITranslateProvider
{
    string Name { get; }
    Task<string> TranslateAsync(string text, string from, string to);
}

public interface IAuthService
{
    Task<bool> SignInAsync(string email, string password);
    Task<bool> SignUpAsync(string email, string password);
    Task SignOutAsync();
    Task<bool> EnsureSessionAsync();   // 启动时恢复会话
}

public sealed class ScreenTranslateFlow
{
    public Task<bool> ConfirmAsync();          // 「是否进行屏幕翻译？」弹窗
    public Task<TranslateResult> RunAsync();   // 截图→OCR→翻译→悬浮窗
}
```

## 6. 数据与安全

| 数据 | 存储位置 | 说明 |
|---|---|---|
| 登录会话 | Windows DPAPI（凭据管理器） | RefreshToken 加密存储 |
| 用户配置 | `%AppData%/BettyTranslate/settings.json` | 快捷键、语言、引擎选择 |
| OCR/翻译缓存 | 内存缓存（LRU） | 不落盘，保护隐私 |
| 用户数据（可选） | Supabase 云端 | 历史记录、用量统计（V1.1） |

## 7. 关键实现要点（踩坑清单）

1. **多显示器**：用虚拟桌面坐标（`VirtualScreen`）而非主屏坐标；每屏按 DPI 缩放换算。
2. **悬浮窗自翻译**：截屏前排除本应用窗口区域；悬浮窗设置 `WS_EX_TRANSPARENT` 时需权衡交互。
3. **全局热键**：RegisterHotKey 在 Win32 层注册，避免注入；冲突时提示修改。
4. **PaddleOCR 集成**：以独立子进程方式运行（JSON 通信，参考 PaddleOCR-json），OCR 崩溃不影响主程序。
5. **翻译并发**：文本块批量翻译，控制并发数（如 5），失败自动重试一次。
