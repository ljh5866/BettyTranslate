# 02 技术选型方案

> 版本：v0.1 | 日期：2026-08-22 | 状态：待评审

## 1. 选型结论（一页速览）

| 维度 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | **WPF + C#（.NET 8）** | Windows 原生、UI 成熟、可直接基于 STranslate 二次开发 |
| 二次开发基础 | **STranslate**（MIT） | 功能最贴合：划词/截图翻译、离线 PaddleOCR、多翻译源、快捷键 |
| OCR 引擎 | **PaddleOCR（默认，离线）** + Windows OCR（快速通道） | 中文识别率高、完全离线、Apache-2.0 可商用 |
| 翻译引擎 | 在线：百度/腾讯/有道/DeepL/Google/OpenAI 可配置；离线：可选 | 在线质量高、离线保隐私 |
| 登录/后端 | **Supabase Auth**（邮箱+密码） | 免自建服务器、免费额度充足、token 管理完善 |
| 截图方案 | Windows Graphics Capture / ScreenCopy（多显示器、多 DPI 正确） | 解决多屏负坐标与 DPI 偏移问题 |
| 悬浮窗 | WPF 无边框置顶半透明窗口 + 全局热键 | 原生实现，参照 Translumo 悬浮窗设计 |

## 2. 桌面技术栈对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **WPF / C#** | Windows 原生、性能好、生态成熟、开源参考最多（STranslate/Translumo） | 仅 Windows | ✅ **采用**（符合单平台目标） |
| Tauri (Rust+Web) | 包体小、跨平台、现代 | 需写 Rust，生态相对年轻 | 备选（若未来跨平台） |
| Avalonia | 跨平台、XAML 语法 | 原生能力需额外适配 | 备选（离线优先参考 pingyi） |
| Electron | 生态最丰富 | 包体大、内存占用高 | 不采用 |
| Python(PyQt/PyWebview) | 开发快 | 打包分发重、性能弱 | 不采用 |

## 3. 关键依赖选型

### 3.1 OCR 引擎

| 引擎 | 离线 | 中文精度 | 速度 | 协议 | 说明 |
|---|---|---|---|---|---|
| **PaddleOCR** | ✅ | 高 | 中 | Apache-2.0 | 首选：内置中英模型，桌面端用 C++ 版（PaddleOCR-json / PaddleOCRApi） |
| **Windows.Media.Ocr** | ✅ | 中 | 快 | 系统内置 | 系统自带 OCR，UI 文本识别快，无需安装模型 |
| Tesseract | ✅ | 中 | 慢 | Apache-2.0 | 传统方案，仅作兜底 |
| EasyOCR | ✅ | 高 | 慢 | MIT | 需 GPU，资源占用大，不优先 |

**决策**：默认 **PaddleOCR**（离线、中文最好）；同时接入 **Windows OCR** 作为快速通道，识别失败时自动降级。

### 3.2 翻译引擎

| 引擎 | 免费额度 | 质量 | 说明 |
|---|---|---|---|
| 百度翻译 | 标准版免费 | 高（中英） | 国内直连，推荐默认 |
| 腾讯云/有道 | 有免费额度 | 高 | 备选 |
| DeepL | API 需 key | 极高 | 可选配置 |
| Google | 免费（网页版） | 高 | 需网络可达 |
| OpenAI / LLM | 按量付费 | 最高（上下文感知） | 进阶选项，可整段智能翻译 |
| Argos Translate / MarianMT | 完全免费 | 中 | 离线翻译，隐私最强（参考 pingyi） |

**决策**：抽象统一 `ITranslateProvider` 接口，默认 **百度翻译**（免费直连），可选 **DeepL / Google / OpenAI / 离线 Argos**。

### 3.3 登录方案：Supabase Auth

- 邮箱 + 密码登录/注册，服务端处理密码哈希与 session
- 客户端使用官方 `supabase-csharp` SDK
- token 持久化到 Windows 凭据管理器（DPAPI 加密）
- 后端可后续扩展：用户表、订阅（Stripe 集成）、翻译用量统计
- 环境内已配置 Supabase 相关 MCP 工具（建表、迁移），可直接对接

### 3.4 截图方案

- 首选 **Windows.Graphics.Capture**（Win10 1903+，GPU 加速，支持多显示器与 DPI）
- 兜底 **CopyFromScreen（GDI）** 兼容老版本
- 多显示器处理：按虚拟桌面坐标 + 每台显示器 DPI 换算（参照 pingyi 踩坑经验）

## 4. 依赖清单（NuGet / 组件）

> 原则（项目约定）：**只引入实际用到的库，不整包导入**。以下为最小必需集。

| 类别 | 库/组件 | 用途 |
|---|---|---|
| 桌面 | WPF（.NET 8 内置）+ `Hardcodet.NotifyIcon.Wpf` | 托盘图标 |
| 热键 | `MouseKeyHook` 或自研 RegisterHotKey | 全局快捷键（优先自研 Win32 RegisterHotKey，零依赖） |
| 截图 | `ScreenCapture`（自研封装 Windows.Graphics.Capture）或 `mss`（跨平台，可选） | 屏幕捕获 |
| OCR | `PaddleOCR-json`（本地进程，JSON 通信）或 `PaddleOCRApi`（C# 封装） | 离线 OCR |
| OCR 备选 | Windows.Media.Ocr（系统 API，无额外包） | 快速识别/降级 |
| 翻译 | `BaiduTranslate`/`Deepl` 等走 HttpClient 自研轻量封装（不引重型 SDK） | 多引擎翻译 |
| 登录 | `supabase-csharp` | Supabase Auth |
| 配置 | 自研 JSON 配置文件（`Microsoft.Extensions.Configuration` 可选） | 本地设置 |
| 日志 | `Serilog`（最小配置） | 本地日志 |

> 注意：STranslate 自带一套插件/服务体系，二次开发时**按需裁剪**，删除不用的服务插件，避免包体臃肿。

## 5. 关键风险与对策

| 风险 | 对策 |
|---|---|
| PaddleOCR 模型体积大（百 MB 级） | 首次使用时按需下载；模型文件独立打包 |
| 多显示器/DPI 截图偏移 | 用 Windows.Graphics.Capture + 虚拟桌面坐标；参考 pingyi 修复方案 |
| 悬浮窗干扰 OCR 结果（自翻译自己） | 截图时排除自身窗口区域（Translumo「Exclude from Capture」思路） |
| 在线翻译限流/封禁 | 多引擎轮换、请求节流、失败重试与提示 |
| 许可证风险 | 基础 STranslate(MIT) + PaddleOCR(Apache-2.0) 均可商用；不引入 GPL 代码 |
